# Survey 220926 — methodology × model sweep

Status: RUNNING. This report fills from
`experiments/220926/results/aggregated.yml` once the sweep completes.
`python3 scripts/aggregate-survey.py` re-renders it at any time.

## Design

- Grid: 4 projects x 3 methods x 3 models x 5 reps = 180 cells, one
  harness process per cell, sequential.
- Projects (ReCodeAgent dataset, crust split, C to Rust): `fft` (233
  C LOC), `totp` (443), `cjson` (1101), `expr` (1110).
- Methods: `monolith` (one ReAct agent plus validator, 14 turns),
  `ledger` (manager-worker scaffold, arXiv:2608.26480 section 3.1, 14
  turns), `recode` (four-phase pipeline, arXiv:2604.0734 Algorithm 1,
  40 turns).
- Models (all ollama): `openbmb/minicpm5-2b:q8_0` (2B), 
  `qwen3.8:27b-mtp-q4_K_M` (27B official), `smtek/Swift-Qwen3.8-27B:dflash2`
  (27B fine-tune). `SparkLLM/Spark-X2.5-4B` was excluded: its
  `spark2_5` GGUF architecture fails to load in the daemon.
- Scoring: the toolchain decides. After every run the harness reruns
  `cargo build` and `cargo test` in the produced workspace
  (`result/per_problem.json`); agent self-reports are recorded but
  never trusted. Traces persist per run as `traces/turns.jsonl`.
- VRAM discipline: every run starts and ends with `--offload`, so
  model switches never co-resident two models.
