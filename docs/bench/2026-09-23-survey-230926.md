# Survey 230926 — methodology sweep on qwen3.8-27B

Status: FINALIZED PARTIAL. The planned grid was 7 projects x 3
methods x 8 models x 5 reps = 840 cells. The sweep ran 4 segments
between 2026-09-23T12:42 and 23:02 +07 and then died with the ollama
daemon during a machine stall. One model (qwen3.8-27B official,
`qwen3.8:27b-mtp-q4_K_M`) completed its full 105-cell grid (7 projects
x 3 methods x 5 reps). The second model (Swift-27B dflash2) reached
only 4 cells, all instant preflight offload aborts against the already
dead daemon. No second-model data exists. Numbers below come from
`experiments/230926/results/aggregated.yml` over the 109 attempt dirs
on disk.

## Executive summary

With generous budgets (120 turns, 11 recode rounds, 60/120 ledger
manager/worker), every method converts the three smallest projects at
a high rate: 39 toolchain-verified passes in 105 cells (37%). Success
concentrates by project size, not by method: `amp` (185 LOC), `ulidgen`
(186), `chtrie` (258) and `murmurhash_c` (324) account for all 39. `gorilla-paper-encode` (635), `approxidate` (1151) and `xopt` (3087)
produce zero verified passes in 45 attempts each. Ledger leads on the
mid-size pair, monolith on the smallest, recode trails everywhere but
still passes 4 of 5 on two projects. The 220926 failure wall is gone:
with 120-turn budgets not one run died of MaxTurnsError.

## Survey design

- Grid: 7 projects x 3 methods x 8 models x 5 reps planned. 1 model
  completed (105 cells), 109 attempt dirs on disk including reruns and
  infra failures.
- Projects (ReCodeAgent dataset, crust split, C to Rust): `amp` (185
  C LOC), `ulidgen` (186), `chtrie` (258), `murmurhash_c` (324),
  `gorilla-paper-encode` (635), `approxidate` (1151), `xopt` (3087).
- Methods (same as 220926):
  - `monolith` — one ReAct agent (write + bash tools) plus a validator.
  - `ledger` — manager-worker scaffold per arXiv:2608.26480 section
    3.1, shared plan/tasks/notes files.
  - `recode` — analyzer, planner, translator, validator loop per
    arXiv:2604.07341 Algorithm 1.
- Budgets (generous, per the 230926 redesign): max_turns 120,
  max_output_tokens 8192, recode 11 rounds, ledger 60 manager / 120
  worker turns, per-run timeout 2 h. The driver logs the turn count
  actually used.
- Model: `qwen3.8:27b-mtp-q4_K_M` (27B official) completed the grid.
- Planned but not run: the 7 other models (both Swift-27B variants,
  minicpm5-2b, granite4.1-3b, lfm2.5-8b, Hemmingway-1, omnimerge-v6).
- Scoring: the toolchain decides. The harness reruns `cargo build` and
  `cargo test` in the produced workspace. A verified pass needs the
  evaluator's own build/test steps in the run result plus a real
  workspace. The harness records agent self-reports and never trusts them.

The 220926 binding constraint is gone. No run hit 120 turns. The
observed ceiling is 35 (amp/monolith/rep5, which still passed).

worker calls are the heaviest. Long-context projects are now the
binding constraint, not turn budgets.

## Failure analysis (109 attempts on disk, incl. 4 non-attempt dirs)

| Class | Count | Share | Reading |
| --- | --- | --- | --- |
| verified pass | 38 | 35% | toolchain-verified end-to-end |
| infra: preflight offload | 57 | 52% | harness harness aborted before the run against a dead ollama daemon (2026-09-23T16:02 and 23:02 machine stalls) |
| output budget | 9 | 8% | model stopped with finish_reason=Length every retry |
| scored, tests failed | 1 | 1% | produced a workspace, tests red |
| task retries exhausted | 1 | 1% | attempt-level errors hidden by the retry wrapper |
| daemon conn lost | 1 | 1% | daemon died mid-run (murmurhash_c/ledger/rep1) |
| invalid tool args | 1 | 1% | model called a tool outside its allowed set |
| other | 1 | 1% | run never started |
| scored, manager self-report only | 0 | 0% | the 220926 ledger trap did not recur |

Readings:

- Project size dominates everything. The 185-324 LOC band converts at
  87-93% per attempt. The 635-3087 LOC band converts at 0%. The
  transition is sharp and sits between 324 and 635 LOC.
- Method differences are second-order and project-dependent. Ledger is
  the only method that passes chtrie (5 of 5). Monolith is the only
  one that passes murmurhash_c (5 of 5). Recode never wins a cell
  outright but still passes 4 of 5 on amp and ulidgen.
- The infra failures (57) carry no information about method or model:
  the daemon was dead when the harness tried its preflight offload.
  We exclude them from all per-method rates.

## Conclusions

- Generous budgets fixed the 220926 failure mode. MaxTurnsError went
  from 42% of runs to zero. Mean turns used stayed under 16 per
  method. The next lever is context/output capacity on the long
  samples, not turn counts.
- The verified-success frontier for qwen3.8-27B on C-to-Rust
  translation sits at roughly 300-350 C LOC for single-shot methods,
  with ledger's manager-worker scaffold the strongest on 250-300 LOC.
  Beyond 600 LOC nothing compiled, so scoring never started.
- The ledger empty-workspace self-report trap from 220926 did not
  recur: all 15 ledger scored runs carry real evaluator steps.
- Infra readiness must gate the sweep: 57 of 109 on-disk attempts are
  preflight aborts against a dead daemon, and the driver treats them
  as consumed failures (no retry). A daemon liveness check before
  each cell would have saved the last segment.
